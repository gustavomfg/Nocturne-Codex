# Nocturne Studio v0.9.0-beta

This release marks the transition from Nocturne Codex to Nocturne Studio and consolidates the project's engineering workspace foundation.

## Highlights

- Product renamed to Nocturne Studio.
- Real execution through Codex CLI with status, approvals and cancellation.
- Workspace Memory and Second Brain integration.
- Separate access paths for ChatGPT/Codex accounts and API providers.
- Improved provider-independent architecture.
- Updated documentation and release metadata.
- Hardened CI, packaging, smoke tests and release validation.

## AI capabilities

### Without Codex CLI

Nocturne Studio can operate as a local workspace and use Review Mode with configured API providers or local runtimes, including:

- OpenAI-compatible APIs
- OpenRouter
- DeepSeek
- Ollama
- LM Studio

### With Codex CLI

Codex CLI is currently required for:

- ChatGPT account access
- Build Mode
- Docs Mode
- Tool execution
- File modifications
- Approvals
- Cancellation through the App Server

Subscriptions from other AI providers are not used directly. They require API access or a supported local runtime.

## Security

- SQLite, WAL and SHM files are restricted to the local user.
- Renderer isolation and explicit IPC boundaries are preserved.
- Credentials remain outside the renderer.
- Production dependency audit reports zero vulnerabilities.

## Validation

- Typecheck and lint
- Automated unit and integration tests
- Playwright regression tests across canonical breakpoints
- Electron build and packaging
- Packaged application smoke test
- Authenticated Codex CLI 0.145.0 and 0.146.0 smoke tests
- Actionlint
- Production dependency audit

## Known limitations

- No self-hosted runner is currently registered for Codex smoke validation.
- The `stable-release` environment does not have code-signing secrets configured.
- Development-only `electron-builder` dependency alerts remain pending a safe upstream fix.
- Build Mode and Docs Mode currently depend on Codex CLI.

## Upgrade notes

Update to the latest beta before reporting or validating issues.

Workspace data remains local, but backups are recommended before testing beta releases.
